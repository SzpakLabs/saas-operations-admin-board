# Requirements: SaaS Ops Admin Dashboard

**Defined:** 2026-06-08
**Core Value:** Show a credible SaaS operations command center that feels ready for a startup or agency admin workflow.

## v1 Requirements

### Demo Access

- [ ] **ACCESS-01**: User can open the app and sign in with demo/fake credentials.
- [ ] **ACCESS-02**: User can navigate main dashboard routes without crashes.
- [ ] **ACCESS-03**: Deployment path requires no private environment variables.

### Operations Workflow

- [ ] **OPS-01**: User can review overview KPIs, revenue/churn context, tickets, alerts, activity, and at-risk accounts.
- [ ] **OPS-02**: User can review customers and customer detail.
- [ ] **OPS-03**: User can review subscriptions.
- [ ] **OPS-04**: User can change ticket state through an existing local action.
- [ ] **OPS-05**: User can resolve, dismiss, or investigate alerts through existing local state.
- [ ] **OPS-06**: User can review settings, team, notifications, or integrations panels.

### Portfolio Packaging

- [ ] **PACK-01**: README explains business problem, solution, stack, local setup, deployment notes, and demo flow.
- [ ] **PACK-02**: A 60-second demo script or portfolio notes exist.
- [ ] **PACK-03**: First screenshot is professional enough for GitHub, LinkedIn, and Upwork.

## v2 Requirements

### Production Features

- **PROD-01**: Real authentication.
- **PROD-02**: Persistent database.
- **PROD-03**: Real billing and support integrations.
- **PROD-04**: Role-based permissions.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Real backend | Mock data is sufficient for the portfolio demo |
| Production auth | Fake auth supports the demo flow |
| Billing integration | Not needed before first outreach |
| AI features | This demo proves SaaS admin UX, not AI automation |
