# Plan 01 - First Screen And Login Demo

<objective>
Polish and verify the public demo entry path so a visitor can sign in with fake credentials, understand the core SaaS operations signals on the overview screen, and navigate the existing dashboard routes without private setup.
</objective>

<must_haves>
## Truths

- D-01: Optimize the existing dashboard overview as the lead portfolio screenshot.
- D-02: Prioritize revenue, churn, tickets, alerts, customer health, activity, and at-risk accounts.
- D-03: Focus visible polish on desktop first-screen quality and fix only obvious mobile breakage.
- D-04: Preserve the operations-manager story from login to overview to supporting workflows.
- D-05: Keep fake auth for v1; do not add real auth, sessions, RBAC, tenancy, or provider setup.
- D-06: Demo credentials must be prefilled or clearly visible.
- D-07: Login must continue redirecting to `/`, and authenticated `/login` visits must continue redirecting to `/`.
- D-08: Do not introduce new auth state beyond the existing Pinia/localStorage mock path unless needed for visible demo clarity.
- D-09: Verify overview, customers, subscriptions, tickets, alerts, and settings navigation.
- D-10: Do not add new routes or dashboard modules.
- D-11: Preserve dashboard layout and Nuxt file-based routing conventions.
- D-12: Navigation fixes target broken links, active-state clarity, or obvious shell polish.
- D-13: Keep backend APIs, production auth, billing, database persistence, broad cleanup, AI features, and full mobile redesign out of scope.
- D-14: Every implementation change must improve demo flow, first screenshot, login, or navigation confidence.
- D-15: Use the existing Nuxt, Vue, Nuxt UI, Pinia, i18n, Chart.js, Tailwind CSS, and typed mock-data patterns.
- D-16: Any browser, form, chat, or user-input testing that enters person names must include "Test" in the person name.
- D-17: Use the existing overview screenshot path.
- D-18: Use prefilled or clearly visible demo credentials.
- D-19: Verify the current route set.
- D-20: Keep portfolio-demo scope over production-platform scope.
</must_haves>
